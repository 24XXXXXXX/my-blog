## 一、Java 基础篇

### Level 1：变量与数据类型

#### 1. Java 有哪些基本数据类型？各自占多少字节？

Java 有 8 种基本数据类型：

- `byte`：1 字节
- `short`：2 字节
- `int`：4 字节
- `long`：8 字节
- `float`：4 字节
- `double`：8 字节
- `char`：2 字节
- `boolean`：Java 规范没有强制规定具体占用大小，逻辑上表示 `true/false`，面试中不要机械回答成固定 `1 bit`

补充说明：

- `char` 采用 Unicode 编码，常见理解是 2 字节。
- `boolean` 在不同 JVM 实现、数组场景下实际存储方式可能不同，所以回答时最好说“语义上表示布尔值，规范未明确固定字节数”。

#### 2. `==` 和 `equals()` 的区别？

- `==`：
  - 基本类型比较的是值
  - 引用类型比较的是对象地址
- `equals()`：
  - `Object` 默认实现本质也是比较地址
  - 很多类如 `String`、`Integer` 重写后，比较的是内容

面试回答建议：

“`==` 是否比较内容，取决于是不是基本类型；`equals()` 是否比较内容，取决于类有没有重写该方法。”

#### 3. 什么是自动装箱与拆箱？有什么坑？

- 自动装箱：基本类型自动转成包装类型，如 `int -> Integer`
- 自动拆箱：包装类型自动转成基本类型，如 `Integer -> int`

常见坑：

- `Integer` 缓存池：`-128 ~ 127` 的值会复用缓存对象
- `Integer a = 127; Integer b = 127; a == b` 为 `true`
- `Integer a = 128; Integer b = 128; a == b` 通常为 `false`
- 包装类型为 `null` 时拆箱会触发 `NullPointerException`
- 混用 `==` 容易因为缓存池导致结果不稳定

#### 4. `String`、`StringBuilder`、`StringBuffer` 的区别？

- `String`：不可变对象，适合读多写少场景
- `StringBuilder`：可变，线程不安全，性能高
- `StringBuffer`：可变，线程安全，性能较低

补充说明：

- `String` 的拼接如果发生在循环中，通常应优先考虑 `StringBuilder`
- 编译期常量拼接会被优化

#### 5. `int` 和 `Integer` 的区别？

- `int` 是基本类型，默认值为 `0`
- `Integer` 是包装类型，本质是对象，默认值为 `null`
- `Integer` 可用于泛型，如 `List<Integer>`
- `Integer` 可以调用方法，适合需要对象语义的场景

### Level 2：面向对象

#### 1. 重载和重写的区别？

重载（Overload）：

- 发生在同一个类中
- 方法名相同，参数列表不同
- 与返回值类型无关

重写（Override）：

- 发生在父子类之间
- 方法名、参数列表相同
- 子类重写父类实现
- 返回类型、访问权限要满足重写规则

一句话概括：

“重载是一个类中多个同名方法的编译期多态，重写是子类改写父类实现的运行时多态基础。”

#### 2. 接口和抽象类的区别？

接口：

- 更强调行为规范
- 支持多实现
- 没有普通实例字段和普通构造器
- JDK 8 后可以有 `default` 和 `static` 方法

抽象类：

- 更适合抽取公共属性和公共逻辑
- 只能单继承
- 可以有成员变量、构造器、普通方法、抽象方法

如何选：

- 需要“能做什么”时优先接口
- 需要“是什么 + 复用公共实现”时优先抽象类

#### 3. Java 的四大特性是什么？

- 封装
- 继承
- 多态
- 抽象

#### 4. 多态的实现条件？

- 存在继承关系或接口实现关系
- 子类重写父类方法
- 父类引用指向子类对象

示例：

```java
Animal animal = new Dog();
animal.eat();
```

编译看左边，运行看右边。

#### 5. Java 是单继承还是多继承？为什么？

- 类是单继承
- 接口可以多实现

原因：

- 类单继承可以降低复杂度，避免多继承带来的菱形继承问题
- 接口多实现可以增强扩展性和抽象能力

### Level 3：集合框架

#### 1. `ArrayList` 和 `LinkedList` 的区别？

`ArrayList`：

- 底层是动态数组
- 支持随机访问，查询快
- 中间位置插入删除可能触发元素移动

`LinkedList`：

- 底层是双向链表
- 插入删除在已知节点位置时更高效
- 随机访问慢，需要顺序遍历

补充：

- 实际业务里 `ArrayList` 用得远多于 `LinkedList`
- 不要只背“增删快”，因为 `LinkedList` 找位置本身就是 O(n)

#### 2. `HashMap` 的底层结构？

JDK 8 中 `HashMap` 底层是：

- 数组
- 链表
- 红黑树

当发生哈希冲突时，元素会先挂到链表上；当链表长度达到 8 且数组容量至少为 64 时，链表会树化为红黑树，以提升查询性能。

#### 3. `HashMap` 的扩容机制？

- 默认初始容量：16
- 默认负载因子：0.75
- 阈值：`容量 * 负载因子`
- 元素个数超过阈值后，容量扩为原来的 2 倍

JDK 8 扩容特点：

- 旧链表节点在新数组中的位置要么不变，要么移动到“原索引 + oldCap”
- 这让迁移效率更高

#### 4. `HashMap` 线程安全吗？用什么替代？

- `HashMap` 线程不安全
- 并发场景下优先使用 `ConcurrentHashMap`

原因：

- 多线程下可能出现数据覆盖、丢失、读取异常
- JDK 7 时代扩容时甚至可能形成链表环

#### 5. `ConcurrentHashMap` 为什么线程安全？JDK 7 和 JDK 8 的区别？

JDK 7：

- 采用 `Segment` 分段锁
- 每个段类似一个小型 `HashMap`

JDK 8：

- 取消 `Segment`
- 使用数组 + 链表/红黑树
- 结合 `CAS` + `synchronized` 控制并发
- 锁粒度更细

#### 6. `HashSet` 的底层是什么？

`HashSet` 底层基于 `HashMap` 实现。

- 元素作为 `HashMap` 的 key 存储
- value 是一个固定的占位对象，通常是 `PRESENT`

### Level 4：多线程与并发

#### 1. 创建线程的几种方式？

- 继承 `Thread`
- 实现 `Runnable`
- 实现 `Callable` 配合 `FutureTask`
- 使用线程池 `ExecutorService`

面试建议：

实际开发中更推荐线程池，因为它能复用线程、控制资源、便于管理。

#### 2. `synchronized` 和 `ReentrantLock` 的区别？

`synchronized`：

- JVM 层面的关键字
- 自动加锁和释放锁
- 使用简单

`ReentrantLock`：

- JDK 提供的 API
- 需要手动 `lock()` / `unlock()`
- 支持公平锁、可中断锁、尝试加锁、条件队列

结论：

- 简单同步优先 `synchronized`
- 需要更灵活控制时用 `ReentrantLock`

#### 3. 线程池的核心参数有哪些？

`ThreadPoolExecutor` 的核心参数：

- `corePoolSize`
- `maximumPoolSize`
- `keepAliveTime`
- `unit`
- `workQueue`
- `threadFactory`
- `handler`

#### 4. 线程池的工作流程？

1. 任务来了，先看核心线程数是否已满
2. 核心线程未满，创建核心线程执行
3. 核心线程已满，尝试进入阻塞队列
4. 队列满了且线程数未到最大线程数，则创建非核心线程
5. 最大线程数也满了，则执行拒绝策略

#### 5. 四种拒绝策略？

- `AbortPolicy`：直接抛异常
- `CallerRunsPolicy`：由调用线程自己执行
- `DiscardPolicy`：直接丢弃
- `DiscardOldestPolicy`：丢弃队列中最早的任务，再尝试提交当前任务

#### 6. `volatile` 的作用？

- 保证可见性
- 禁止指令重排序
- 不保证原子性

补充：

- `volatile` 适合“一写多读”或状态标记类场景
- 例如停止线程的标记位

#### 7. `ThreadLocal` 是什么？有什么问题？

`ThreadLocal` 用于给每个线程维护一份独立变量副本，线程之间互不干扰。

典型场景：

- 用户上下文
- 数据库连接上下文
- 事务上下文

问题：

- 可能导致内存泄漏
- 原因是 `ThreadLocalMap` 的 key 是弱引用，但 value 不是弱引用
- 如果线程长期存活且未调用 `remove()`，value 可能残留

结论：

用完要及时 `remove()`，尤其在线程池场景下。

## 二、Spring Boot 篇

### Level 1：基础概念

#### 1. Spring Boot 的核心特性？

- 自动配置
- 起步依赖
- 内嵌 Web 服务器
- 生产级监控与治理能力（如 Actuator）

#### 2. Spring Boot 自动配置的原理？

核心链路：

`@SpringBootApplication` -> `@EnableAutoConfiguration` -> 自动配置类加载 -> 条件注解按需生效

面试展开可以这样答：

- Spring Boot 启动时会扫描自动配置元数据
- 将候选自动配置类加载进来
- 每个自动配置类通常搭配 `@ConditionalOnClass`、`@ConditionalOnMissingBean`、`@ConditionalOnProperty` 等条件注解
- 满足条件才创建对应 Bean
- 最终实现“约定大于配置”

补充：

- 早期版本常见说法是 `spring.factories`
- 新版本 Spring Boot 也引入了新的自动配置导入机制
- 面试里提到“本质是自动配置类 + 条件装配”最稳妥

#### 3. `@SpringBootApplication` 包含哪些注解？

- `@SpringBootConfiguration`
- `@EnableAutoConfiguration`
- `@ComponentScan`

#### 4. `application.yml` 和 `application.properties` 的区别？

- `yml` 层次结构清晰，适合复杂配置
- `properties` 简单直接，适合扁平配置

补充：

- `yml` 支持更直观的列表、对象嵌套
- 团队内保持风格统一更重要

### Level 2：核心机制

#### 1. Spring 的 IOC 和 AOP 是什么？

IOC：

- 控制反转
- 对象的创建和依赖关系维护交给 Spring 容器管理

AOP：

- 面向切面编程
- 在不修改业务代码的前提下，对公共逻辑进行增强

典型用途：

- 日志
- 权限
- 事务
- 性能统计

#### 2. AOP 的实现方式？

- JDK 动态代理：针对接口
- CGLIB 动态代理：针对类

一般来说：

- 有接口优先 JDK 动态代理
- 没有接口则使用 CGLIB

#### 3. Spring Bean 的生命周期？

常见回答顺序：

1. 实例化
2. 属性赋值
3. 调用 `Aware` 接口方法
4. `BeanPostProcessor` 前置处理
5. 初始化方法
6. `BeanPostProcessor` 后置处理
7. Bean 可被使用
8. 容器关闭时执行销毁方法

#### 4. Bean 的作用域？

- `singleton`
- `prototype`
- `request`
- `session`
- `application`

#### 5. `@Autowired` 和 `@Resource` 的区别？

- `@Autowired` 默认按类型注入，来自 Spring
- `@Resource` 默认按名称注入，来自 Jakarta/Javax 规范

补充：

- `@Autowired` 可配合 `@Qualifier`
- `@Resource(name = "...")` 可以显式指定 Bean 名称

#### 6. Spring Boot 常用注解？

- `@RestController`
- `@RequestMapping`
- `@Service`
- `@Component`
- `@Repository`
- `@Configuration`
- `@Bean`

### Level 3：进阶应用

#### 1. Spring Boot 如何统一异常处理？

使用：

- `@ControllerAdvice`
- `@ExceptionHandler`

建议：

- 自定义统一返回结构
- 区分业务异常和系统异常
- 记录完整日志但避免向前端暴露敏感堆栈

#### 2. Spring Boot 如何配置拦截器？

步骤：

1. 实现 `HandlerInterceptor`
2. 重写 `preHandle`、`postHandle`、`afterCompletion`
3. 通过 `WebMvcConfigurer` 注册拦截器

#### 3. Spring Boot 如何配置跨域？

常见方式：

- 方法或类上使用 `@CrossOrigin`
- 通过 `WebMvcConfigurer#addCorsMappings` 统一配置

#### 4. Spring Boot 的配置文件加载优先级？

通用回答：

- 命令行参数优先级高
- 外部配置通常高于内部配置
- 同位置下，通常 `properties` 优先级高于 `yml`

面试中建议强调：

“具体优先级层次较多，但大方向是命令行 > 外部配置 > 内部配置。”

#### 5. 如何理解 Spring Boot 的 Starter 机制？

Starter 本质上是：

- 一组依赖聚合
- 搭配自动配置

作用：

- 开发者引入一个 starter
- Spring Boot 自动完成依赖装配和 Bean 配置
- 实现开箱即用

## 三、MyBatis 篇

### Level 1：基础

#### 1. `#{}` 和 `${}` 的区别？

- `#{}`：预编译占位符，底层使用 `PreparedStatement`，可以防 SQL 注入
- `${}`：字符串直接拼接，存在 SQL 注入风险

结论：

- 能用 `#{}` 就不要用 `${}`
- `${}` 只在动态表名、动态排序字段等极少数场景谨慎使用

#### 2. MyBatis 中 `resultMap` 和 `resultType` 的区别？

- `resultType`：适合字段名和对象属性名基本一致的简单映射
- `resultMap`：适合复杂映射、自定义字段映射、关联对象映射

这是一个常见考点，很多人会口误把两者都说成 `resultType`。

#### 3. MyBatis 的接口绑定有几种方式？

- XML 映射文件
- 注解方式，如 `@Select`、`@Insert`

#### 4. MyBatis 如何实现分页？

- 使用分页插件，如 `PageHelper`
- 手动编写 `limit`

补充：

- 大数据量深分页场景要注意性能问题
- 可以考虑基于主键或游标分页

### Level 2：进阶

#### 1. MyBatis 的一级缓存和二级缓存？

一级缓存：

- 作用域是 `SqlSession`
- 默认开启

二级缓存：

- 作用域是 `Mapper namespace`
- 需要手动开启

补充：

- 二级缓存命中条件更严格
- 实际企业项目里往往更依赖 Redis 等外部缓存

#### 2. MyBatis 如何处理关联查询？

- `association`：一对一
- `collection`：一对多

#### 3. MyBatis 的动态 SQL 有哪些标签？

- `if`
- `choose`
- `when`
- `otherwise`
- `where`
- `set`
- `foreach`
- `trim`
- `sql`

#### 4. MyBatis 插件运行原理？

MyBatis 插件基于 JDK 动态代理，对四大核心对象进行拦截：

- `Executor`
- `StatementHandler`
- `ParameterHandler`
- `ResultSetHandler`

可以在这些对象的方法调用前后织入自定义逻辑。

## 四、MySQL 篇

### Level 1：基础 SQL

#### 1. SQL 的基本 CRUD 语句？

```sql
SELECT * FROM table_name WHERE condition;

INSERT INTO table_name(col1, col2) VALUES (v1, v2);

UPDATE table_name SET col1 = v1 WHERE condition;

DELETE FROM table_name WHERE condition;
```

#### 2. `WHERE` 和 `HAVING` 的区别？

- `WHERE`：分组前过滤行
- `HAVING`：分组后过滤组

#### 3. `GROUP BY` 和 `ORDER BY` 的区别？

- `GROUP BY`：分组聚合
- `ORDER BY`：结果排序

#### 4. `INNER JOIN`、`LEFT JOIN`、`RIGHT JOIN` 的区别？

- `INNER JOIN`：返回两边都匹配的数据
- `LEFT JOIN`：返回左表全部数据和右表匹配数据
- `RIGHT JOIN`：返回右表全部数据和左表匹配数据

---

### Level 2：索引

#### 1. 索引的作用？

- 加快查询速度
- 降低磁盘 I/O 次数
- 提高排序、分组、关联查询效率

代价：

- 占用额外存储空间
- 会降低插入、更新、删除性能

#### 2. 索引的底层数据结构？为什么用 B+ 树？

MySQL InnoDB 常用 B+ 树。

原因：

- 非叶子节点只存键，不存完整数据，扇出更大
- 树更矮，磁盘 I/O 更少
- 叶子节点通过链表连接，天然适合范围查询

#### 3. 聚簇索引和非聚簇索引的区别？

聚簇索引：

- 数据行本身按主键组织存储
- InnoDB 的主键索引就是聚簇索引

非聚簇索引（二级索引）：

- 叶子节点存储索引列值和主键值
- 查到主键后再回主键索引拿完整数据

#### 4. 什么是回表？如何避免？

回表：

- 先通过二级索引查到主键
- 再根据主键去聚簇索引查完整数据

避免方式：

- 使用覆盖索引
- 即查询字段都能直接从索引中拿到

#### 5. 什么是最左前缀原则？

联合索引如 `(a, b, c)`，查询条件应尽量从左到右连续使用索引列。

例如：

- `a`
- `a, b`
- `a, b, c`

这些都更容易充分利用索引。

#### 6. 联合索引 `(a, b, c)`，`WHERE a = 1 AND c = 3` 能走索引吗？

- `a` 一般可以利用索引
- `c` 通常无法充分利用联合索引，因为跳过了 `b`

面试更严谨的说法：

- “能部分走索引，但不能像连续命中 `(a, b)` 那样高效。”
- MySQL 8.0 某些场景下可能有优化能力，但不能把它当常规答案。

#### 7. 索引失效的场景？

- 对索引列使用函数
- 隐式类型转换
- `LIKE '%xx'`
- `OR` 两侧字段索引使用不佳
- 不满足最左前缀原则
- 选择性太差，优化器可能放弃索引

#### 8. `EXPLAIN` 的关键字段？

- `type`：访问类型
- `key`：实际使用的索引
- `rows`：预估扫描行数
- `Extra`：额外信息

常见关注点：

- 是否出现 `Using index`
- 是否出现 `Using filesort`
- 是否出现 `Using temporary`

---

### Level 3：事务与锁

#### 1. 事务的四大特性（ACID）？

- 原子性
- 一致性
- 隔离性
- 持久性

#### 2. 事务的隔离级别？

- 读未提交
- 读已提交
- 可重复读
- 串行化

MySQL InnoDB 默认是可重复读。

#### 3. 什么是脏读、不可重复读、幻读？

脏读：

- 读到了别人未提交的数据

不可重复读：

- 同一事务中，两次读取同一条记录结果不同

幻读：

- 同一事务中，两次按条件查询，返回的记录条数不同

#### 4. MySQL 如何解决幻读？

InnoDB 在不同场景下通过：

- MVCC
- Next-Key Lock（临键锁）

共同降低或避免幻读问题。

面试中可以回答：

“快照读依赖 MVCC，当前读依赖临键锁。”

#### 5. 乐观锁和悲观锁的区别？

乐观锁：

- 假设冲突少
- 常见实现是版本号、CAS

悲观锁：

- 假设冲突多
- 典型做法是 `select ... for update`

#### 6. InnoDB 的行锁有哪几种？

- `Record Lock`：记录锁
- `Gap Lock`：间隙锁
- `Next-Key Lock`：临键锁，记录锁 + 间隙锁

#### 7. MVCC 的实现原理？

核心组成：

- 隐藏字段，如 `trx_id`、`roll_pointer`
- `Undo Log`
- `ReadView`

理解方式：

- 每次事务修改数据都会保留历史版本
- 一致性读通过版本链和可见性规则决定当前事务能看到哪个版本

## 五、Redis 篇

### Level 1：基础

#### 1. Redis 是什么？为什么快？

Redis 是基于内存的高性能键值数据库。

快的原因：

- 基于内存
- 单线程模型避免了大量锁竞争
- I/O 多路复用
- 数据结构设计高效

#### 2. Redis 的五种基本数据类型？

- `String`
- `List`
- `Set`
- `Hash`
- `ZSet`

#### 3. Redis 为什么常被说成单线程？

通常是指：

- 命令执行主线程是单线程模型

优势：

- 避免线程切换和锁竞争开销

补充：

- Redis 新版本并不是所有模块都绝对单线程，比如网络 I/O、后台持久化等会有其他线程参与
- 面试里不要把“整个 Redis 完全单线程”说得太绝对

---

### Level 2：应用场景

#### 1. 什么时候用 Redis？

- 缓存热点数据
- 分布式锁
- 计数器
- 排行榜
- Session 共享
- 消息队列或延迟队列类场景

#### 2. Redis 缓存穿透、击穿、雪崩？

缓存穿透：

- 查询根本不存在的数据
- 请求直接打到数据库

解决：

- 缓存空值
- 布隆过滤器

缓存击穿：

- 热点 key 失效瞬间，大量请求同时访问数据库

解决：

- 互斥锁
- 热点数据不过期或逻辑过期

缓存雪崩：

- 大量 key 在同一时间失效，数据库压力骤增

解决：

- 过期时间打散
- 多级缓存
- 限流降级

#### 3. Redis 和数据库双写一致性怎么做？

常见方案是 Cache Aside Pattern：

1. 先更新数据库
2. 再删除缓存

为什么不是先删缓存再更新数据库：

- 容易出现并发下旧值重新写回缓存的问题

进一步优化：

- 延迟双删
- 基于消息队列异步删除缓存
- 基于 binlog 订阅工具做最终一致性

#### 4. Redis 的持久化方式？

- `RDB`：快照方式，恢复快，可能丢失最近数据
- `AOF`：追加日志，数据更安全，文件更大，恢复较慢

实际生产通常会同时使用。

#### 5. Redis 的过期删除策略？

- 惰性删除
- 定期删除

#### 6. Redis 的内存淘汰策略？

常见类别：

- `LRU`
- `LFU`
- 随机淘汰
- 不淘汰

面试里可以补一句：

“具体策略取决于配置，不同版本可选项略有差异。”

---

### Level 3：高可用

#### 1. Redis 集群方案？

- 主从复制
- 哨兵模式
- Cluster 分片集群

#### 2. Redis Sentinel 的工作原理？

Sentinel 主要负责：

- 监控主从节点状态
- 故障通知
- 自动故障转移

#### 3. Redis Cluster 的数据分片？

- Redis Cluster 把数据划分到 `16384` 个哈希槽
- key 通过哈希计算映射到某个槽
- 槽再分配给不同节点

### Level 1：基础

#### 1. 为什么要用消息队列？

- 异步处理

- 流量削峰
- 日志与事件驱动处理

#### 2. 常见的消息队列？

#### 3. 消息队列的模型？

- 点对点模型（Queue）

### Level 2：核心问题

#### 1. 如何保证消息不丢失？

可以从三段来答：

- 生产者：发送确认机制，如 confirm
- MQ：消息持久化、集群高可用
- 消费者：手动 ACK，消费成功后再确认

#### 2. 如何保证消息不重复消费（幂等性）？

常见方案：

- 消息唯一 ID
- 数据库唯一约束
- Redis 去重
- 幂等表

本质：

- MQ 很难绝对保证“只投递一次”
- 业务侧要保证“多次消费结果一致”

#### 3. 如何保证消息顺序性？

- 同一业务主键路由到同一个队列或分区
- 由单消费者顺序消费

#### 4. 消息积压怎么处理？

- 扩容消费者
- 提升单次消费能力
- 排查消费端瓶颈
- 必要时临时旁路处理历史消息

#### 5. RabbitMQ 的交换机类型？

- `Direct`
- `Fanout`
- `Topic`
- `Headers`

## 七、AI 集成篇（LangChain4j + RAG + 本地大模型）

### Level 1：概念

#### 1. 什么是 LangChain4j？为什么要用它？

LangChain4j 是 Java 生态里用于集成大模型能力的开发框架。

它的价值在于：

- 统一接入不同大模型
- 支持 Prompt、RAG、工具调用、Agent 等能力
- 降低 Java 项目接入 AI 的复杂度

#### 2. 什么是 RAG（检索增强生成）？

RAG 是一种“先检索、再生成”的架构。

流程是：

- 从知识库检索相关内容
- 将检索结果拼接到 Prompt
- 再让模型基于上下文生成答案

#### 3. 为什么需要 RAG，而不是直接问大模型？

原因：

- 大模型知识有时间边界
- 不知道企业私有数据
- 直接生成容易产生幻觉

RAG 的核心价值就是：

- 让回答基于可控知识源
- 提高准确性和可解释性

---

### Level 2：技术实现

#### 1. RAG 的完整流程？

```text
文档加载 -> 文本清洗 -> 文本分块 -> 向量化 -> 存入向量数据库
用户提问 -> 问题向量化 -> 相似度检索 -> 上下文组装 -> 大模型生成回答
```

#### 2. 什么是向量数据库？常见的有哪些？

向量数据库用于存储和检索高维向量数据，核心能力是相似度检索。

常见产品：

- Milvus
- Pinecone
- Chroma
- Weaviate
- Elasticsearch 的向量检索能力

#### 3. 文本分块的策略？

- 固定大小分块
- 按段落分块
- 按句子分块
- 递归字符分块
- 语义分块

分块原则：

- 太大，召回不精准
- 太小，上下文不完整

#### 4. Embedding 模型是什么？

Embedding 模型负责把文本转成向量。

特点：

- 语义相近的文本，在向量空间中距离更近

用途：

- 相似度检索
- 聚类
- 召回

#### 5. 如何自建本地知识库？

一个典型流程：

1. 收集企业文档
2. 清洗与结构化处理
3. 文本分块
4. 调用 Embedding 模型生成向量
5. 存入本地向量库
6. 查询时按问题向量召回相关片段
7. 组装 Prompt 交给大模型回答

---

### Level 3：本地部署

#### 1. 如何本地部署大模型？

常见方案：

- Ollama
- vLLM
- llama.cpp

这些方案通常可以加载本地模型文件，并通过 HTTP 暴露推理接口。

#### 2. Ollama 是什么？如何使用？

Ollama 是一个本地大模型运行框架，适合快速部署和调用模型。

例如：

```bash
ollama run qwen2:7b
```

#### 3. LangChain4j 如何对接本地大模型？

```java
ChatLanguageModel model = OllamaChatModel.builder()
    .baseUrl("http://localhost:11434")
    .modelName("qwen2:7b")
    .build();
```

#### 4. 本地部署大模型的硬件要求？

经验性回答：

- 7B 模型通常需要更高内存或显存资源
- 量化后部署门槛会下降
- 模型越大，对显存、内存、带宽要求越高

更好的面试表达：

“具体资源和模型格式、量化方式、上下文长度、推理框架有关，7B/13B 只是粗略参考。”

#### 5. 什么是模型量化？

量化是把模型权重从高精度格式压缩到更低精度格式，如：

- FP16 -> INT8
- FP16 -> INT4

作用：

- 降低显存和存储占用
- 提高部署可行性

代价：

- 可能损失一定精度

#### 6. LangChain4j 如何实现 RAG？

```java
EmbeddingStore<TextSegment> embeddingStore = ...;
EmbeddingModel embeddingModel = ...;

ContentRetriever retriever = ContentRetriever.builder()
    .embeddingStore(embeddingStore)
    .embeddingModel(embeddingModel)
    .build();

Assistant assistant = AiServices.builder(Assistant.class)
    .chatLanguageModel(model)
    .contentRetriever(retriever)
    .build();
```

#### 7. RAG 中如何提高检索质量？

- 优化分块策略
- 使用更合适的 Embedding 模型
- 混合检索（向量 + 关键词）
- 重排序
- 多路召回
- Query Rewrite

## 八、前端篇（Vue3 基础了解）

#### 1. Vue3 和 Vue2 的区别？

- Vue3 引入 Composition API
- 对 TypeScript 支持更好
- 响应式从 `Object.defineProperty` 升级为 `Proxy`
- 支持 Fragment 等能力

#### 2. Vue3 的组合式 API 和选项式 API 的区别？

- 组合式 API：按功能组织代码，复用性更强
- 选项式 API：按 `data`、`methods`、`computed` 等选项组织

#### 3. `ref` 和 `reactive` 的区别？

- `ref` 常用于基本类型，也可包装对象
- `reactive` 主要用于对象和数组
- `ref` 在 JavaScript 中访问通常要 `.value`

#### 4. Vite 和 Webpack 的区别？

- Vite 基于原生 ESM，开发启动快，热更新快
- Webpack 更成熟，生态更丰富，传统项目中使用广泛

#### 5. Axios 拦截器的作用？

- 请求拦截：统一加 Token、公共参数
- 响应拦截：统一处理错误码、登录失效、异常提示

#### 6. Vue3 生命周期钩子？

常见有：

- `onMounted`
- `onUpdated`
- `onUnmounted`

## 九、架构篇

### Level 1：单体架构

#### 1. 单体架构的优缺点？

优点：

- 开发简单
- 部署方便
- 调试容易
- 本地事务处理简单

缺点：

- 系统变大后代码臃肿
- 模块耦合高
- 扩展性差
- 技术栈受限

---

### Level 2：微服务架构

#### 1. 什么是微服务架构？

微服务是把一个大型系统拆分成多个可独立开发、部署、扩展的服务。

#### 2. 微服务的核心组件？

- 注册中心
- 配置中心
- 网关
- 服务调用组件
- 负载均衡
- 熔断降级
- 链路追踪
- 日志与监控

#### 3. Spring Cloud 和 Spring Cloud Alibaba 的区别？

Spring Cloud：

- 提供完整微服务治理体系
- 传统 Netflix 技术栈中部分组件已停更或弱化

Spring Cloud Alibaba：

- 更贴合国内常用中间件生态
- 常见组合是 Nacos、Sentinel、Seata、Dubbo

#### 4. Nacos 的作用？

- 注册中心
- 配置中心

#### 5. Gateway 网关的作用？

- 路由转发
- 统一鉴权
- 限流熔断
- 日志记录
- 统一跨域与灰度治理

#### 6. 服务间如何调用？

- `RestTemplate`
- `OpenFeign`
- `Dubbo`

#### 7. 什么是服务熔断和降级？

熔断：

- 当失败率达到阈值时，暂时切断对下游服务的调用

降级：

- 当系统压力过大或下游不可用时，返回兜底结果

#### 8. 分布式事务如何解决？

常见方案：

- Seata
- 消息最终一致性
- 最大努力通知
- TCC
- Saga

#### 9. 单体架构什么时候该拆分为微服务？

常见判断标准：

- 业务复杂度提升
- 团队规模扩大
- 模块需要独立扩容
- 发布频率高且相互影响严重

## 十、项目实战与场景题

#### 1. 如何设计一个 AI 旅游推荐系统的架构？

可按以下思路回答：

1. 用户请求先进入网关层
2. 推荐服务接收请求并识别用户画像、预算、目的地偏好
3. 从旅游知识库、攻略库、酒店和景点数据中做召回
4. 通过 RAG 检索相关资料
5. 大模型基于检索结果生成个性化路线建议
6. 热门推荐和静态攻略可进入 Redis 缓存
7. 埋点用户反馈，用于后续优化推荐策略

#### 2. 教育平台如何用 AI 实现智能答疑？

思路：

1. 把课程资料、讲义、题库构建成知识库
2. 学生提问后先进行问题理解和改写
3. 通过 RAG 检索最相关内容
4. 大模型基于课程资料生成答案
5. 对问答结果做审核、记录和反馈闭环

#### 3. 宠物社区如何处理高并发场景（如秒杀领养）？

常见方案：

- Redis 预扣库存
- MQ 异步削峰
- 数据库最终一致性
- 接口限流
- 防重提交

#### 4. 如何保证接口的安全性？

- Token 鉴权，如 JWT
- 接口签名
- 时间戳和随机数防重放
- 限流
- HTTPS
- 敏感接口审计日志

#### 5. 如何设计一个接口限流方案？

可以从实现位置和算法两方面回答。

实现位置：

- 网关层限流
- 应用层限流
- 分布式限流

常见算法：

- 令牌桶
- 漏桶
- 滑动窗口

常见实现：

- Redis + Lua
- Sentinel
- Gateway 限流过滤器

#### 6. 大搜业务或第三方搜索对接的技术难点有哪些？

- 高并发请求处理
- 数据同步一致性
- 接口幂等
- 超时重试
- 失败补偿
- 监控告警
