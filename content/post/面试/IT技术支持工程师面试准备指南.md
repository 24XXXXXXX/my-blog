## 二、核心概念速查

### 2.1 什么是ERP

**ERP（Enterprise Resource Planning，企业资源计划）** 是一种集成化的信息管理系统，用于管理企业的核心业务流程。

**核心功能：**
- 财务管理（会计、预算、报表）
- 供应链管理（采购、库存、物流）
- 生产制造（计划、排程、质量控制）
- 人力资源（招聘、薪酬、考勤）
- 客户关系管理（销售、服务）

**主要价值：**
- 统一数据源，消除信息孤岛
- 自动化业务流程，减少人工操作
- 实时数据分析，支持决策
- 提高运营效率和协同能力

**常见产品：** SAP、Oracle ERP、用友、金蝶等

> 简单说，ERP就是把企业各部门的业务流程整合到一个系统里，让数据流通、流程标准化。

---

### 2.2 OA/CRM/OMS/WMS/TMS解析

这些都是企业常用的业务系统，各司其职：

| 系统 | 全称 | 核心功能 | 典型产品 |
|------|------|----------|----------|
| **OA** | Office Automation | 办公自动化：审批流程、公文流转、会议管理 | 钉钉、飞书、泛微 |
| **CRM** | Customer Relationship Management | 客户关系管理：线索、商机、合同、售后 | Salesforce、纷享销客 |
| **OMS** | Order Management System | 订单管理：下单到完成的全流程 | 旺店通、聚水潭、有赞 |
| **WMS** | Warehouse Management System | 仓储管理：入库、出库、盘点、库位管理 | 富勒、唯智、巨沃 |
| **TMS** | Transportation Management System | 运输管理：路线规划、运力调度、运费结算 | 蓝桥、科箭 |

**它们之间的关系：**

```
CRM（获客）→ OMS（接单）→ WMS（发货）→ TMS（配送）
                                    ↑
                              ERP（统筹）
                              OA（协同）
```

> ERP是"大管家"，这些系统是各领域的"专业选手"，通常需要和ERP打通数据。

---

### 2.3 SaaS模式特点

**SaaS（Software as a Service，软件即服务）** 是一种云端部署的软件交付模式。

| 对比项 | 传统软件 | SaaS软件 |
|--------|----------|----------|
| 部署方式 | 本地服务器 | 云端 |
| 付费模式 | 一次性购买 | 按年/月订阅 |
| 维护责任 | 企业自己 | 软件厂商 |
| 升级方式 | 手动升级 | 自动更新 |
| 数据存储 | 本地 | 云端 |

## 三、IT技术支持岗位解析

### 3.1 岗位职责

IT技术支持是企业内部的"技术后勤"，确保员工能正常使用各种IT设备和系统。

**日常工作内容：**
- **硬件维护**：电脑、打印机、网络设备的安装和故障排除
- **软件支持**：系统安装、软件配置、账号权限管理
- **网络管理**：网络连接问题、VPN配置、WiFi维护
- **用户支持**：解决员工遇到的各种技术问题（Helpdesk）
- **资产管理**：IT设备采购、盘点、报废

**工作方式：**
- **工单系统**：员工提问题 → 派单 → 解决 → 关闭
- **现场/远程支持**：简单问题远程处理，复杂问题上门服务
- **巡检**：定期检查设备和系统运行状态

### 3.2 技能要求

| 技能领域 | 具体内容 |
|----------|----------|
| 操作系统 | Windows/Mac/Linux基础操作与故障排除 |
| 网络基础 | TCP/IP、DNS、DHCP、HTTP/HTTPS |
| 数据库 | SQL基础查询、MySQL常见操作 |
| 办公软件 | Office套件、企业协作工具 |
| 硬件维修 | 电脑组装、外设维护 |
| 沟通能力 | 向非技术人员解释技术问题 |

### 3.3 职业发展路径

```
初级IT支持 → 高级IT工程师 → IT主管 → IT经理 → CIO
                ↓
        网络工程师/系统工程师/安全工程师（专精方向）
```

## 四、技术基础复习

### 4.1 数据库/SQL

**常见面试题：**

```sql
-- 1. LEFT JOIN 和 INNER JOIN 的区别
-- INNER JOIN：只返回两表都匹配的记录
-- LEFT JOIN：返回左表所有记录，右表无匹配则显示NULL

-- 2. 查询某店铺最近7天的订单总数
SELECT COUNT(*) AS order_count
FROM orders
WHERE shop_id = 'xxx'
  AND create_time >= DATE_SUB(NOW(), INTERVAL 7 DAY);

-- 3. 什么是索引？什么时候需要加索引？
-- 索引类似于书的目录，加快查询速度
-- 适合加索引的场景：WHERE条件字段、JOIN关联字段、ORDER BY排序字段
```

### 4.2 HTTP基础

| HTTP状态码 | 含义 |
|------------|------|
| 200 | 请求成功 |
| 301 | 永久重定向 |
| 302 | 临时重定向 |
| 400 | 请求参数错误 |
| 401 | 未授权 |
| 403 | 禁止访问 |
| 404 | 资源未找到 |
| 500 | 服务器内部错误 |

**GET vs POST：**

| 对比项 | GET | POST |
|--------|-----|------|
| 参数位置 | URL中 | 请求体中 |
| 安全性 | 较低（参数暴露在URL） | 较高 |
| 数据长度 | 有限制 | 无限制 |
| 幂等性 | 是 | 否 |
| 使用场景 | 查询数据 | 提交/修改数据 |


### 4.4 网络基础

**TCP/IP四层模型：**
```
应用层（HTTP、FTP、DNS）
    ↓
传输层（TCP、UDP）
    ↓
网络层（IP、ICMP）
    ↓
网络接口层（以太网、WiFi）
```

**Cookie vs Session：**

| 对比项 | Cookie | Session |
|--------|--------|---------|
| 存储位置 | 客户端浏览器 | 服务器 |
| 安全性 | 较低 | 较高 |
| 大小限制 | 4KB左右 | 无明确限制 |
| 生命周期 | 可设置过期时间 | 默认会话结束即失效 |

## 五、业务场景面试题（重点！）

### 场景1：客户反馈"库存数量不对"

**排查思路：**
1. 确认是哪个平台/仓库的库存
2. 检查是否有未完成的订单占用库存
3. 查看库存同步日志，是否有同步失败
4. 检查是否有退货/调拨单未处理
5. 对比平台后台和ERP系统的库存数据
6. 检查是否有并发订单导致超卖

### 场景2：客户反馈"订单同步失败"

**排查思路：**
1. 确认平台授权是否过期（Token失效）
2. 检查API接口是否有报错日志
3. 查看平台是否有系统维护通知
4. 检查网络连接是否正常
5. 检查订单状态是否符合同步条件
6. 尝试手动触发同步

### 场景3：多个客户同时找你解决问题

**优先级排序原则：**
1. **按紧急程度**：影响业务流程的优先（如无法发货、无法收款）
2. **按客户等级**：VIP客户/大客户优先
3. **按问题复杂度**：简单问题快速解决，复杂问题记录后跟进
4. **按影响范围**：影响多人的问题优先于个人问题

### 场景4：客户反馈"系统访问卡顿"

**排查思路：**
1. 确认是个别用户还是普遍现象
2. 检查用户网络环境（带宽、延迟）
3. 检查服务器负载（CPU、内存、磁盘IO）
4. 查看数据库慢查询日志
5. 检查是否有大量数据导入/导出任务
6. 确认CDN/缓存是否正常

## 六、软技能问题

### 6.1 如何向不懂技术的客户解释问题？

**回答要点：**
- 用生活化的类比，避免技术术语
- 分步骤说明，确认对方理解
- 提供操作指引而非理论解释
- 保持耐心，不表现出不耐烦

**示例：**
> "您可以把数据库想象成一个图书馆，索引就像图书馆的目录卡片。没有目录卡片，找书需要一本本翻；有了目录卡片，可以直接定位到书的位置。"

### 6.2 遇到客户情绪激动/投诉怎么办？

**处理步骤：**
1. **先倾听**：让客户把问题说完，不打断
2. **表示理解**："我理解您的感受，这个问题确实影响了您的使用"
3. **不争辩**：不对抗，不对立
4. **记录问题**：详细记录客户反馈的问题
5. **承诺时间**：给出明确的解决时间预期
6. **跟进反馈**：问题解决后主动回访

### 6.3 为什么选择做技术支持？

**回答思路：**
- 表达对技术的热情
- 强调喜欢与人沟通、帮助他人
- 说明技术支持是积累经验的好起点
- 展示对公司的了解和认可

## 九、面试技巧总结

### 自我介绍模板（1-2分钟）

```
面试官您好，我是XXX，来自XXX大学XXX专业。

在校期间，我学习了XXX、XXX等课程，对XXX有扎实的基础。
同时，我通过XXX项目/实习，积累了XXX方面的实践经验。

我对技术支持岗位很感兴趣，因为我认为技术支持不仅是解决技术问题，
更是帮助用户提升效率、改善体验的过程。

我选择贵公司是因为XXX（结合公司产品/业务特点），
希望能在这个岗位上不断学习成长，为团队创造价值。

谢谢！
```

### 回答问题的STAR法则

- **S（Situation）**：描述背景和情境
- **T（Task）**：说明你的任务和目标
- **A（Action）**：具体采取的行动
- **R（Result）**：最终的结果和收获
