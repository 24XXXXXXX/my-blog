## 一、单体架构

### 1. 单体架构的优缺点？

优点：

- 开发简单
- 部署方便
- 调试容易
- 本地事务简单

缺点：

- 代码膨胀
- 模块耦合高
- 扩展能力差
- 发布影响面大

## 二、微服务架构

### 1. 什么是微服务架构？

把一个大型应用拆分成多个可以独立开发、部署、扩容的服务。

### 2. 微服务核心组件有哪些？

- 注册中心
- 配置中心
- 网关
- 服务调用
- 负载均衡
- 熔断降级
- 链路追踪
- 日志监控

### 3. Spring Cloud 和 Spring Cloud Alibaba 的区别？

Spring Cloud：

- 微服务治理体系完整

Spring Cloud Alibaba：

- 更贴合国内常用中间件生态
- 常见组件有 Nacos、Sentinel、Seata、Dubbo

### 4. Nacos 的作用？

- 服务注册与发现
- 配置中心

### 5. Gateway 的作用？

- 路由转发
- 鉴权
- 限流
- 日志
- 统一跨域处理

### 6. 服务间如何调用？

- `RestTemplate`
- `OpenFeign`
- `Dubbo`

### 7. 什么是熔断和降级？

熔断：

- 当下游异常达到阈值后临时断开调用

降级：

- 非核心功能返回兜底结果

### 8. 分布式事务如何解决？

常见方案：

- Seata
- TCC
- Saga
- 消息最终一致性

### 9. 单体什么时候拆微服务？

- 业务复杂度高
- 团队规模扩大
- 模块需要独立扩容
- 发布频繁且相互影响严重

## 三、项目场景题

### 1. 如何设计一个 AI 旅游推荐系统？

可按链路回答：

1. 用户请求进入网关
2. 推荐服务获取用户画像与需求
3. 检索景点、酒店、攻略知识库
4. 通过 RAG 召回相关资料
5. 大模型生成个性化推荐
6. Redis 缓存热门结果
7. 记录反馈用于后续优化

### 2. 教育平台如何实现 AI 智能答疑？

1. 课程资料构建知识库
2. 学生提问后进行问题理解
3. RAG 检索课程资料
4. 模型结合检索结果回答
5. 记录问答反馈，持续优化

### 3. 宠物社区如何处理高并发秒杀领养？

- Redis 预扣库存
- MQ 异步下单
- 数据库最终一致性
- 接口限流
- 防重提交

### 4. 如何保证接口安全？

- JWT 或 Token 鉴权
- 接口签名
- 时间戳和随机数防重放
- HTTPS
- 限流
- 审计日志

### 5. 如何设计接口限流方案？

可从两方面回答：

- 部署位置：网关层、应用层、分布式限流
- 核心算法：令牌桶、漏桶、滑动窗口

常见实现：

- Redis + Lua
- Sentinel
- Gateway 限流

### 6. 搜索业务或第三方搜索接入的技术难点？

- 高并发流量处理
- 数据同步一致性
- 接口幂等
- 超时重试
- 失败补偿
- 监控告警

## 四、准备建议

微服务和场景题不要只讲组件名，更重要的是讲清楚：

1. 为什么这样设计
2. 流量高峰怎么处理
3. 一致性怎么保证
4. 异常时如何兜底

这样回答会比单纯背术语更像真实项目经验。
