Redis 和消息队列是后端面试中的两大中间件重点，尤其是缓存问题、持久化、高可用，以及 MQ 的不丢失、幂等性和顺序性。
<!--more-->

## 一、Redis 基础

### 1. Redis 是什么？为什么快？

Redis 是基于内存的高性能键值数据库。

快的原因：

- 基于内存
- 主线程执行命令模型减少锁竞争
- I/O 多路复用
- 数据结构设计高效

### 2. Redis 的五种基本数据类型？

- `String`
- `List`
- `Set`
- `Hash`
- `ZSet`

### 3. Redis 为什么常被说成单线程？

通常是指命令执行主线程是单线程模型。

注意：

- 不要绝对化理解成整个 Redis 所有模块都单线程

## 二、Redis 常见应用

### 1. Redis 能做什么？

- 缓存热点数据
- 分布式锁
- 计数器
- 排行榜
- Session 共享
- 延迟队列类场景

### 2. 缓存穿透、击穿、雪崩分别是什么？

缓存穿透：

- 请求不存在的数据

解决：

- 布隆过滤器
- 缓存空值

缓存击穿：

- 热点 key 失效瞬间流量打到数据库

解决：

- 互斥锁
- 逻辑过期
- 热点数据不过期

缓存雪崩：

- 大量 key 同时过期

解决：

- 过期时间随机化
- 限流降级
- 多级缓存

### 3. Redis 和数据库双写一致性怎么做？

常见方案是 Cache Aside：

1. 更新数据库
2. 删除缓存

可进一步优化为：

- 延迟双删
- MQ 异步删缓存
- 订阅 binlog 保证最终一致性

### 4. Redis 持久化方式？

- `RDB`
- `AOF`

生产常常组合使用。

### 5. Redis 的过期删除策略？

- 惰性删除
- 定期删除

### 6. Redis 的内存淘汰策略？

常见包括：

- `LRU`
- `LFU`
- 随机淘汰
- 不淘汰

## 三、Redis 高可用

### 1. Redis 集群方案？

- 主从复制
- Sentinel
- Cluster

### 2. Sentinel 的作用？

- 监控
- 通知
- 自动故障转移

### 3. Cluster 如何分片？

- 使用 `16384` 个哈希槽

## 四、消息队列基础

### 1. 为什么使用消息队列？

- 异步处理
- 系统解耦
- 流量削峰
- 日志和事件驱动

### 2. 常见消息队列有哪些？

- RabbitMQ
- RocketMQ
- Kafka
- ActiveMQ

### 3. 消息模型有哪些？

- 点对点
- 发布订阅

## 五、MQ 核心问题

### 1. 如何保证消息不丢失？

从三个环节回答：

- 生产者发送确认
- MQ 持久化和高可用
- 消费者手动 ACK

### 2. 如何保证消息不重复消费？

核心是幂等设计：

- 消息唯一 ID
- 数据库唯一约束
- Redis 去重
- 幂等表

### 3. 如何保证消息顺序性？

- 相同业务 key 发往同一队列或分区
- 单消费者顺序处理

### 4. 消息积压怎么处理？

- 增加消费者
- 提升消费速度
- 排查消费端阻塞问题

### 5. RabbitMQ 的交换机类型？

- `Direct`
- `Fanout`
- `Topic`
- `Headers`

## 六、面试重点

Redis 和 MQ 最容易被追问的点通常是：

- 缓存穿透、击穿、雪崩
- Redis 持久化
- Redis 高可用
- MQ 不丢失
- MQ 幂等性
- MQ 顺序性

这些题建议优先准备成可口述的标准答案。
